# Итоговые решения

Результат обсуждения требований из `task.md`: интерфейс на React для отправки и получения текстовых сообщений через GREEN-API. Внешний вид повторяет web.max.ru, а мессенджер — WhatsApp (задание это допускает): инстанс GREEN-API работает с WhatsApp, методы API для MAX (например, `checkAccount`) на нём отвечают 404.

## Факты об API GREEN-API (WhatsApp)

- Базовый URL: `{apiUrl}/waInstance{idInstance}/{method}/{apiTokenInstance}`, где `apiUrl` задаётся в `.env` переменной `VITE_GREEN_API_URL` (по умолчанию `https://api.green-api.com`).
- CORS разрешён: сервер отвечает с `Access-Control-Allow-Origin: *`, поэтому запросы идут напрямую из браузера, прокси не нужен.
- Личный чат адресуется `chatId` вида `79991234567@c.us`. В таком же виде `senderData.chatId` приходит во входящих уведомлениях.
- `checkWhatsapp` принимает `{ phoneNumber }` (только цифры, международный формат) и возвращает `{ existsWhatsapp }`.
- `getContactInfo` принимает `{ chatId }` и возвращает, среди прочего, `contactName` (из телефонной книги) и `name` (из профиля WhatsApp). Оба поля могут быть пустыми.
- Получение через HTTP API работает так: `receiveNotification` → `deleteNotification`, очередь FIFO, уведомления хранятся 24 часа. У инстанса должны быть настройки `webhookUrl: ""`, `incomingWebhook: "yes"`, `outgoingWebhook: "yes"`.

## Проект и инструменты

- Проект находится в папке `test-task-green-api/` (свой git-репозиторий), `task.md` лежит снаружи.
- Vite + React + TypeScript, пакетный менеджер pnpm.
- ESLint + Prettier. Границы FSD проверяются через `eslint-plugin-boundaries`, без steiger.
- Тесты на Vitest покрывают применение уведомлений, дедупликацию и форматтеры.
- README описывает, как настроить инстанс и как запустить проект.
- GitHub Actions, деплоя и push на GitHub нет.

## Архитектура (Feature-Sliced Design)

- `app/` — store, `styles/tokens.css` (CSS-переменные), выбор экрана: вход или мессенджер.
- `pages/` — `login`, `messenger`.
- `widgets/` — `nav-rail`, `chat-list-panel`, `chat-window`, `instance-settings-banner`.
- `features/` — `auth`, `send-message`, `receive-notifications`, `create-chat`, `leave-chat`, `fix-instance-settings`, `logout`.
- `entities/` — `session`, `chat`, `message`.
- `shared/` — `api/green-api` (клиент и типы уведомлений), `ui` (Avatar, Button, Input, Icon, Popover), `lib` (форматирование времени и номера, безопасный `localStorage`), `config`.

Правила:

- Каждый slice отдаёт публичный API через `index.ts`, импорты идут через алиасы `@/…`.
- Состояние хранится в Zustand, store на каждую сущность, сохраняется через `persist` в `localStorage`. История лежит под ключом `gapi-max:{idInstance}`. При выходе удаляются только учётные данные.
- Логика применения уведомлений и дедупликации — чистые функции, их можно тестировать отдельно.
- Роутера нет: экран выбирается условным рендером, открытый чат хранится в состоянии.
- Стили — CSS Modules и CSS-переменные.

## Вход

- Отдельный экран — карточка по центру. Поля:
  - `idInstance`;
  - `apiTokenInstance` (скрытый ввод с кнопкой «показать»);
- Под формой — ссылка на console.green-api.com.
- При нажатии «Войти» вызывается `getStateInstance`. Пускаем только при `authorized`:
  - 401/403 → «неверные данные»;
  - `notAuthorized` → «инстанс не авторизован».
- Затем вызывается `getSettings`. Если `webhookUrl` не пустой или выключены `incomingWebhook`/`outgoingWebhook`, показываем баннер с кнопкой «Исправить», которая вызывает `setSettings`. Без согласия пользователя настройки не меняются.

## Получение сообщений

- Цикл последовательный: `receiveNotification?receiveTimeout=20` → обработка → `deleteNotification`, всегда и для любых типов уведомлений, иначе очередь встанет. Цикл останавливается при выходе и размонтировании.
- При 401/403 происходит выход на экран входа с сообщением «сессия недействительна».
- При ошибке сети или 5xx запрос повторяется с растущей паузой 1 → 2 → 4 … до 30 секунд, а под заголовком «Чаты» показывается «Соединение…».
- Входящее сообщение от неизвестного `chatId` автоматически создаёт чат. Название — `senderName`, а если его нет, то номер телефона (или `chatId`, если это не личный чат). Такое название считается заглушкой: как только в уведомлении приходит имя собеседника, чат переименовывается.
- Уведомления `outgoingMessageReceived` и `outgoingAPIMessageReceived` тоже добавляются в ленту. Дубликаты отсекаются по `idMessage`.
- Непрочитанные сообщения считаются для неактивного чата и обнуляются при его открытии. Счётчика в заголовке вкладки нет.

## Отправка

- `sendMessage` вызывается с числовым `chatId`. Сообщение сразу появляется в ленте.
- Статусы: часы — отправляется, одна галочка — отправлено, красный значок с кнопкой «повторить» — ошибка. «Доставлено» и «прочитано» не отображаются.
- Поле ввода: Enter отправляет, Shift+Enter переносит строку, поле растёт по высоте, лимит 4000 символов. Пустые сообщения и сообщения из одних пробелов не отправляются.
- Кнопка «отправить» стоит вместо микрофона.

## Создание чата

- Кнопка «+» сразу открывает модальное окно с полем «Номер телефона».
- Номер нормализуется: только цифры, «8…» и «9…» (10 цифр) приводятся к «7…», допустимо 10–15 цифр.
- `checkWhatsapp` проверяет, что номер есть в WhatsApp. Чат создаётся с `chatId` `{номер}@c.us` и названием-заглушкой — отформатированным номером (`+7 999 123-45-67`), затем сразу открывается. Параллельно `getContactInfo` запрашивает имя собеседника (`contactName`, иначе `name`) и подставляет его. Если имени нет или запрос не удался, остаётся номер, а имя подтянется из следующего уведомления по этому чату. Ответ собеседника приходит с тем же `chatId` и попадает в этот чат.
- Ошибки показываются под полем: номер не похож на телефон, «номер не зарегистрирован в WhatsApp», нет сети, 429/466 (лимит проверок номеров).
- ⚠️ Открытый вопрос — LID. `checkWhatsapp` может вернуть в поле `chatId` идентификатор вида `123456789012345@lid` вместо номера. Если WhatsApp пришлёт ответ собеседника с `senderData.chatId` в формате `@lid`, он не совпадёт с чатом `{номер}@c.us` и появится отдельным чатом. Сейчас это не обрабатывается: примеры входящих уведомлений в документации GREEN-API используют `@c.us`. Варианты решения — хранить `chatId` из ответа `checkWhatsapp` как псевдоним чата и сводить уведомления по нему или по номеру отправителя. Вернуться после проверки на реальном инстансе.

## Выход из чата

- При наведении на строку чата на месте времени появляется красная иконка «Покинуть чат» (на сенсорных экранах — у открытого чата). Меню нет, клик сразу убирает чат.
- Удаление локальное: из списка убираются чат и его история, открытый чат закрывается. В WhatsApp переписка остаётся, и новое сообщение от собеседника снова создаст чат.

## Дизайн (по скриншотам web.max.ru)

- Одна светлая тема. Интерфейс на русском, время в 24-часовом формате, для старых сообщений в списке показывается дата («23 сент.»).
- Левая панель содержит только «Настройки» (учётные данные, выход).
- Список чатов:
  - заголовок «Чаты» и синяя кнопка «+»;
  - в каждой строке: аватар, название, превью последнего сообщения, время, счётчик непрочитанных;
  - активный чат выделен.
- Аватар — цветной кружок с первой буквой названия, цвет зависит от `chatId`.
- Чат:
  - шапка со стрелкой «назад», аватаром, названием и номером или `chatId`;
  - пузыри сообщений с временем и галочкой внутри;
  - разделители по датам;
  - кнопка «вниз»;
  - фон со своим SVG-узором;
  - поле ввода в виде «пилюли» внизу.
- Звонков, видео, поиска в шапке, скрепки, эмодзи, микрофона, папок и отметки «был в сети» нет.
- На мобильном (до 768px) показывается либо список, как на скриншоте, либо чат на весь экран; «назад» возвращает к списку. На десктопе «назад» закрывает чат и показывает «Выберите чат».
